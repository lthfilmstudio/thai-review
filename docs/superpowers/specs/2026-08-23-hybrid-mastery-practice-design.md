# 清心安神：混合型熟練練習設計

建立：2026-08-23（Asia/Taipei）

狀態：Nalin 已確認產品方向，待依本規格另寫實作計畫

優先順序：**B 全課程熟練速度 ＞ A 主動輸出能力 ＞ C 穩定性與介面**

> 本規格的「C」雖排第三，資料遺失、跳卡、帳號混用等正確性問題仍是功能前置條件，不屬於可延後的介面美化。

## 1. 背景與問題

清心安神已經有課程卡、SRS、完整重新掃描、弱項、教師音檔、每日遊戲、進度統計與雲端同步。目前缺少一條整合路徑，使用者仍要在「全部重新走一遍」「先清到期」「補救不熟」「練到能說」之間切換。

這次設計把四種任務合併成一條每日路徑：每次只做一個 10–15 分鐘的小回合，由系統依當下資料混合出題。一天仍可把約 1 小時當作柔性衝刺目標，分多次完成；達標後不鎖住功能，也不形成處罰。

### 1.1 本次要解決的核心問題

1. 到期卡一多，完整掃描容易被擠掉，無法穩定往課程後段前進。
2. 只照課程順序掃描，真正快忘記或一直答錯的內容又得不到優先補救。
3. 目前的主要複習多是看泰文後辨認意思，不能直接代表看到中文就能說出泰文。
4. 錯題只在結果頁列出或反覆改寫同一張卡的成績，都無法同時兼顧教學與誠實記錄。
5. 長佇列、游標與整包覆寫式同步容易在中途離開、多裝置或資料更新時產生跳卡與資料遺失。

## 2. 設計目標

### 2.1 必須達成

- 每個小回合都讓完整掃描穩定前進，常態最低配置為 40%。
- 到期卡按現有 SRS 與相對逾期程度處理，但不無限吞掉整天的練習量。
- 首次答錯的卡在同一回合有限度回鍋，答對後記錄「救回」，但不洗掉第一次結果。
- 加入由中文提示主動說出泰文的練習，結果與辨認型 SRS 分開保存。
- 同一張卡在同一回合只占一個位置；跨回合也遵守每日去重規則。
- 每回答一張就保存；中途離開後依事實重建，不依賴一條巨大、持久化的佇列。
- 用可解釋的規則調整下一回合比例，不導入黑箱個人化演算法。
- 進度頁能回答「走到哪裡、舊卡有沒有堆積、錯題有沒有救回、能不能自己說」四個問題。

### 2.2 本版不做

- 語音辨識、發音評分或錄音回放。
- 自由聊天型 AI 老師、即時生成課程內容。
- FSRS 或其他 SRS 核心演算法替換。
- XP、排行榜、社交、付費貨幣、扣心、倒數或每日懲罰。
- 讓使用者手動微調四軌比例。
- 無限錯題循環。

## 3. 學習設計依據

本設計採用下列概念，但只保留符合單人、低壓、課程導向產品的部分：

| 概念 | 在清心安神中的做法 |
|---|---|
| Spaced practice | 到期軌繼續使用現有 SRS，把正式間隔和一般練習分開。 |
| Retrieval practice | 掃描與到期卡在揭曉前不顯示答案，先要求回想。 |
| Interleaving | 小回合交錯掃描、到期、弱項與輸出，不連刷一整段相同任務。 |
| Successive relearning | 答錯後短間隔回鍋；之後仍依 SRS 在不同日期再次出現。 |
| Productive recall | 從中文提示產出泰文，獨立記錄「會辨認」與「說得出來」。 |
| Scaffolded feedback | 第一次不會才逐步提供 Karaoke、關鍵詞與教師音檔。 |

### 3.1 坊間 App 概念的取捨

- 借鑑 Duolingo 的短回合、單一路徑、錯題回顧與由辨認逐步走向產出；不採用壓力型 streak、付費限制或依賴麥克風的評分。
- 借鑑 Busuu 的課程內情境化輸出與練習後回饋；不採用第一版就上生成式 AI 對話。
- 借鑑 Memrise 的真人／母語音訊與低壓實用句；本專案直接使用既有教師音檔。
- 借鑑 Speak 的 voice-first 精神；第一版只要求真的說出口並自行評估，不做 ASR。

## 4. 核心模型：四軌小回合

每次按「開始下一個小回合」時，才依最新資料建立約 10 張的暫時佇列。完成或離開後不保存整條佇列，只保存每張卡已發生的事實。

### 4.1 常態配置

| 軌道 | 10 張回合的基準名額 | 目的 |
|---|---:|---|
| 完整掃描 Sweep | 4 | 保證全課程持續向前。 |
| 到期複習 Due | 3 | 挽救正在流失的記憶。 |
| 弱項修補 Weak | 2 | 修補 Again、Hard、低 ease factor 或近期錯題。 |
| 中文提示輸出 Output | 1 | 把辨認能力轉成主動說出泰文。 |

常態交錯示意：

```text
掃描 → 到期 → 掃描 → 弱項 → 到期
→ 掃描 → 開口 → 弱項 → 到期 → 掃描
```

實際順序可依候選卡分散課次，但不得連續超過 3 張同一軌或同一課次；不需要追求每回合完全相同的排列。

### 4.2 軌道碰撞與去重

同一張卡可能同時符合多個軌道，分配優先序為：

```text
Due ＞ Sweep ＞ Weak ＞ Output
```

- 已到期又尚未掃描：標示為「到期」，正式更新 SRS，同時把本輪掃描狀態標成已完成。
- 尚未掃描又屬於舊弱項：標示為「掃描」，第一次結果可重新加入弱項池。
- 已選進任何軌道：其他軌道不得再選同一卡。
- 因去重或候選不足空出的名額，依 `Sweep → Due → Weak → Output` 補滿；Due 仍受 40% 上限限制。
- 若不足 10 張，不製造重複卡；以實際可用張數完成較短回合。

「掃描至少 40%」指至少 4 個名額由 Sweep 軌抽取；Due 卡若另外完成掃描，只會讓實際覆蓋前進得更快。

## 5. 各軌進入與作答規則

四軌的按鈕文字不同，但底層先正規化成三種結果，供動態比例、弱項與統計共用：

| 正規化結果 | Sweep | Due | Weak | Output |
|---|---|---|---|---|
| `failure` | 沒想起來 | Again | 沒想起來 | 想不起來 |
| `partial` | 有點模糊 | Hard | 有點模糊 | 差一點 |
| `success` | 想起來了 | Good／Easy | 想起來了 | 說出來了 |

- `failure` 或 `partial` 都可以進入補救回鍋。
- 只有第一次 `failure` 後來變成 `success` 才計為「救回」；`partial` 的改善另保存在事件裡，不灌高救回率。
- 回合第一次作答成功率為 `success / first attempts`，回鍋不進分母或分子。

### 5.1 Sweep：完整掃描

候選條件：

- 依 `state.lessons` 和課內卡片順序排列。
- 本輪掃描開始後尚未有 unaided first response 的卡。
- 已在本回合被 Due 選中的卡排除。

作答流程：

1. 正面只顯示泰文，可主動播放教師音檔。
2. 使用者先回想中文意思。
3. 點擊後顯示中文、Karaoke 與音檔。
4. 選「沒想起來／有點模糊／想起來了」。

結果：

- 三種結果都算這張卡已正式掃描一次。
- 「沒想起來」和「有點模糊」加入辨認弱項。
- Sweep 結果不改 SRS 的 `nextReviewAt`、interval 或 ease factor。

### 5.2 Due：正式 SRS

候選條件：

- `nextReviewAt <= now`。
- 使用現有相對逾期程度排序。
- 同一相對逾期程度時，優先較久未正式評分者，再以課次交錯。

作答流程：

1. 正面只顯示泰文，可主動播放教師音檔。
2. 揭曉中文、Karaoke 與音檔。
3. 選 Again／Hard／Good／Easy。

結果：

- 每次出題只有第一次評分能更新 SRS。
- Again 或 Hard 可觸發同回合補救回鍋，但回鍋結果不得再次改寫 SRS。
- 若這張卡尚未完成本輪掃描，第一次正式評分同時完成掃描。

### 5.3 Weak：辨認弱項修補

候選優先序：

1. 最近正式評為 Again。
2. 最近正式評為 Hard。
3. 本輪或最近練習選「沒想起來／有點模糊」。
4. ease factor 偏低或近期重複失敗。

限制：

- 已在本回合 Due 或 Sweep 的卡排除。
- 同一張卡每天最多進入一次正式弱項修補；同回合的錯題回鍋另計。
- Weak 結果更新補救紀錄，不提前重排正式 SRS。

### 5.4 Output：中文提示主動輸出

候選條件：

- 最近正式評分為 Good 或 Easy，避免一開始就要求輸出尚未辨認的材料。
- 泰文、中文、Karaoke 與教師音檔資料完整。
- 優先完整句與生活實用短語，單字僅在候選不足時補入。
- 候選中先排前次輸出「想不起來」，再排「差一點」，最後才排尚未嘗試的穩定卡。
- 同一張卡每天最多出現一次。

作答流程：

1. 只顯示中文。
2. 使用者先把泰文說出口；不錄音、不倒數。
3. 點擊後顯示泰文、Karaoke 與教師音檔。
4. 選「想不起來／差一點／說出來了」。

結果：

- 寫入獨立的 production result，不改辨認型 SRS。
- 「想不起來／差一點」加入輸出弱項池，日後仍從中文提示再次練習。

## 6. 錯題回鍋

錯題回鍋用來在同一回合完成教學；統計仍保留第一次結果，不會被洗成全對。

### 6.1 回鍋階梯

1. **第一次需要補救**：揭曉答案、播放或讓使用者播放教師音檔，提示跟讀一次；插回 3 張後。
2. **第二次仍需補救**：增加 Karaoke 或關鍵詞支架；插回 4–6 張後。
3. **第三次仍需補救**：停止當日循環，顯示「今天先到這裡」，列入明日優先弱項。

同一張卡因此最多有第一次作答加 2 次回鍋。

回鍋不占四軌的初始名額，也不算成新的唯一卡；因此一個「約 10 張」的小回合在錯題很多時可能有額外互動，但使用者仍可隨時選擇離開。

### 6.2 記錄原則

- 同一組練習事件中的 `phase: first` 永遠保留第一次結果。
- 後續答對記為 `recovered: true`。
- 到期卡第一次 Again，不會因回鍋答對被改成 Good。
- 回合正確率只計第一次作答；救回率另行顯示。

## 7. 下一回合的動態比例

比例只在小回合邊界調整，進行中不突然換規則。

### 7.1 四種模板

| 狀況 | Sweep | Due | Weak | Output |
|---|---:|---:|---:|---:|
| 常態 | 4 | 3 | 2 | 1 |
| 到期壓力 | 4 | 4 | 2 | 0 |
| 本回合失誤較多 | 4 | 3 | 3 | 0 |
| 到期清空且穩定 | 6 | 0 | 2 | 2 |

### 7.2 判斷順序

1. 上一回合第一次結果為 `failure` 或 `partial` 的卡至少 3 張：使用「本回合失誤較多」。
2. 否則，回合開始時待複習至少 20 張：使用「到期壓力」。
3. 否則，待複習為 0，且上一回合第一次作答成功率至少 70%：使用「到期清空且穩定」。
4. 其他狀況使用常態。

若沒有上一回合資料，使用常態模板。閾值是第一版可測的明確常數；上線後只根據真實使用紀錄調整，不加入機器學習。

### 7.3 不變護欄

- Sweep 不低於 40%，除非已沒有可掃描卡。
- Due 不高於 40%。
- Output 最先讓位給 Weak 或 Due。
- 配置只影響下一個回合；隔天重新以當天資料計算。

## 8. 每日去重與離開安全

每日維護四組狀態：

```text
reviewedToday
sweptToday
weakPracticedToday
outputTriedToday
```

規則：

- 同一卡同一天只接受一次正式 Due 評分。
- Sweep 完成後，當天其他回合不再以 Sweep 身分出現。
- Weak 每天最多一次，錯題在原回合的 2 次回鍋除外。
- Output 每天最多一次。
- 每回答一張立即保存事件與衍生狀態。
- 中途離開不保存整條 queue；下次進入時排除已完成項目並重建。
- 若 App 在保存前崩潰，最多只需重做當下尚未確認的 1 張。

## 9. 完整掃描的完成定義

一次掃描完成代表：

> 從該輪開始後，每張課程卡至少有一次沒有先看到答案的首次回想。

### 9.1 哪些算完成

- Sweep 卡完成第一次回答。
- Due 卡在答案揭曉前完成正式回答。
- 同一卡的補救回鍋不增加覆蓋數。
- 遊戲中直接看過答案不算掃描。

### 9.2 課程資料變動

- 掃描期間新增的卡接在本輪尾端，不重置整輪。
- 已刪除的卡從分母與完成集合移除。
- 卡片內容修訂但 ID 不變，不重置完成狀態；若未來需要因重大改版重練，應另開新掃描輪次。
- 不以扁平游標判定進度，只以穩定 card ID 的完成集合判定。

### 9.3 完成後

完成畫面顯示：

```text
第一輪完整掃描完成
全部課程卡都已經正式回想過一次
```

完成後進入鞏固期，由 Due、Weak 與 Output 主導。是否開始下一輪完整掃描由使用者主動選擇，不自動無限重跑。

## 10. 使用者介面

### 10.1 首頁

唯一主要入口：

```text
開始下一個小回合
約 10 張・可隨時停下

掃描 4・到期 3・弱項 2・開口 1
```

若比例調整，補一行原因，例如：「到期內容較多，這回合先多複習 1 張」。不要要求使用者先選模式。

### 10.2 回合中

- 頂部只顯示 `4 / 10 · 弱項修補`。
- 不顯示倒數、剩餘分鐘或落後警告。
- 卡片正面不提前露出中文或 Karaoke。
- 教師音檔按鈕在正面與揭曉面都可用；不自動強迫播放。
- 「今天先到這裡」隨時可用。

### 10.3 回合摘要

```text
這回合完成了
掃描前進 4 張
清掉 3 張到期
救回 1 張弱項
從中文提示說出 1 句
2 張明天優先
```

按鈕：

- 再來一個小回合
- 今天先到這裡

## 11. 進度頁與課程地圖

### 11.1 四項核心數據

| 問題 | 指標 |
|---|---|
| 課程走到哪裡？ | 本輪掃描 `completed / total`。 |
| 舊內容有沒有堆積？ | 目前到期數與最近 7 天趨勢。 |
| 錯題有沒有救回？ | 首次失敗數、同回合救回數與救回率。 |
| 能不能自己說？ | 本週輸出「說出來／差一點／想不起來」分布。 |

不得把「已掃描」寫成「已精通」。第一版不顯示無法嚴格定義的總精通率。

### 11.2 每週自然語句

```text
這週新掃過 126 張、清掉 84 張到期內容、
救回 19 張弱項，也從中文提示說出了 11 句泰文。
```

### 11.3 課程地圖狀態

- 尚未掃描
- 已經遇過
- 目前較弱
- 穩定保留

單元摘要示意：

```text
中 2-4：已掃描 78 / 92
較弱 6 張・到期 3 張・可輸出 12 句
```

## 12. 資料模型

系統分成三本帳；三本帳保存學習事實，queue 永遠由這些事實重新衍生。

### 12.1 正式 SRS 帳

沿用既有 `state.progress[cardId]`，保存正式評分、interval、ease factor 與 `nextReviewAt`。只有 Due 軌第一次作答可更新。

### 12.2 完整掃描帳

每次互動各寫一筆 append-only event；第一次作答與後續回鍋用同一個 `attemptId` 串起來：

```js
{
  schemaVersion: 1,
  cycleId: "uuid",
  startedAt: "ISO timestamp",
  completedCardIds: ["card-id"],
  completedAt: null
}
```

- `completedCardIds` 以集合語意合併。
- 不保存扁平位置游標。
- 新掃描輪次使用新的 `cycleId`，不同輪次不得混合完成集合。

### 12.3 練習事件帳

概念結構：

```js
{
  eventId: "uuid",
  attemptId: "uuid",
  cardId: "card-id",
  dayKey: "YYYY-MM-DD",
  mode: "sweep | due | weak | output",
  phase: "first | retry1 | retry2",
  result: "failure | partial | success",
  attemptedAt: "ISO timestamp",
  deviceId: "..."
}
```

- `eventId` 必須全域唯一，跨裝置以 `eventId` 去重後做 set union。
- `attemptId` 代表同一張卡在同一回合的整組作答；`phase` 區分第一次與最多 2 次回鍋。
- `firstResult`、`recovered` 與救回率均由同一 `attemptId` 的事件衍生，不以後寫結果覆蓋先前事件。
- Due 的 `phase: first` 事件與 SRS 寫入必須形成同一個可恢復動作；若其中一側失敗，下次載入要能補齊或安全重做，不得一半成功後重複評分。
- 週統計由事件衍生；長期資料量策略在實作計畫中依現有儲存限制決定，不先加入不必要的後端。

### 12.4 帳號與同步隔離

- 所有同步資料必須以目前帳號／使用者 ID 分區。
- 切換帳號前取消或忽略舊帳號仍在進行的 request。
- 登出後舊 request 回來不得再寫入目前 local state。
- 合併事件採 union；正式 SRS 進度依單卡可驗證的更新時鐘合併，不用整包 last-write-wins。

## 13. 既有資料搬移

- 完整保留現有 SRS 進度與歷史。
- 現有 resweep 已完成 card ID 可轉成第一輪的 `completedCardIds`。
- 不沿用舊的扁平 queue position；已完成集合才是可信資料。
- 現有每日遊戲紀錄繼續獨立，不轉成 SRS 成績。
- migration 必須可重複執行且不重複建立事件。
- migration 前後分別驗證卡片總數、已有 SRS 卡數與 resweep 完成集合大小。

## 14. 實作前置修復

這些問題會破壞新系統的資料可信度，必須先處理：

1. `src/cloud-sync.js`：修正 pull 後可能丟掉本機修改或歷史紀錄的合併問題。
2. `src/cloud-sync.js`：隔離帳號切換、登出與 in-flight sync。
3. `src/today.js`／`src/resweep.js`：修正交錯插入重新掃描卡後可能跳過較早卡片的問題。
4. 音檔載入路徑：避免上一張音訊或過期 manifest 被帶到下一張。
5. reset 路徑：清除進度時不得留下無效 auth 或同步 metadata。

前置修復只修正資料與流程正確性，不順手重構其他模組。

## 15. 實作階段

### Phase 0：資料安全

修正同步、帳號隔離、resweep 跳卡與音檔狀態。

完成條件：離線、多裝置、帳號切換、登出重登都不丟紀錄或互相污染。

### Phase 1：四軌 queue engine

完成候選池、比例模板、動態選擇、去重、課次交錯與回鍋上限。先做純函式與單元測試，再接 UI。

完成條件：任何候選組合都能建立最多 10 張的唯一卡片回合，且遵守 Sweep floor、Due cap 和每日限制。

### Phase 2：練習畫面與逐張保存

完成首頁入口、四種卡片、揭曉流程、中途離開與回合摘要。

完成條件：每張確認後立即持久化，重整或背景化後已完成項目不會重做。

### Phase 3：掃描輪次與課程地圖

完成 stable-ID 覆蓋集合、資料變動規則、單元狀態與完成畫面。

完成條件：所有現存卡各完成一次後才宣告整輪完成；新增與刪除卡不造成整輪歸零或幽靈卡。

### Phase 4：輸出能力與進度頁

完成中文提示輸出、production weakness、救回率、趨勢與每週摘要。

完成條件：Output 與 Weak 結果不改正式 SRS，所有指標都能回推到練習事件。

## 16. 驗收條件

### 16.1 Queue 與學習規則

- [ ] 常態 10 張回合可產生 4／3／2／1 配置。
- [ ] 到期壓力、失誤較多、到期清空三種模板按定義切換。
- [ ] 同一 `cardId` 不會在同一回合重複占位。
- [ ] Sweep 至少 40%，Due 至多 40%，候選不足除外。
- [ ] Due＋Sweep 重疊卡只出現一次，但兩項狀態都正確更新。
- [ ] 同日去重與錯題回鍋例外符合第 8 節。
- [ ] 第三次仍需補救時停止當日回鍋並進入明日優先。

### 16.2 SRS 與事件誠信

- [ ] 只有 Due 第一次作答會更新 SRS。
- [ ] Again 回鍋答對不會被覆寫成 Good。
- [ ] Sweep、Weak、Output 都不提前移動 `nextReviewAt`。
- [ ] 每次 first response 和 recovery 都可由事件重建。
- [ ] 遊戲結果不會被算成 SRS grade。

### 16.3 離線、同步與搬移

- [ ] 回答一張後立即重整，該張不會遺失或重複評分。
- [ ] 兩裝置離線各做一部分，重新連線後事件與掃描集合為 union。
- [ ] 帳號切換與登出中的舊 request 不會寫進新帳號。
- [ ] 既有 SRS、日誌、遊戲與 resweep 已完成進度在 migration 後保留。
- [ ] migration 執行兩次結果相同。

### 16.4 使用者介面

- [ ] 首頁只有一個明確的混合回合主入口。
- [ ] 回合開始前看得到四軌組成與調整原因。
- [ ] 卡片正面不洩漏答案，教師音檔可用且不播放錯卡。
- [ ] 任意時點可選「今天先到這裡」。
- [ ] 回合摘要分開顯示掃描、到期、救回與輸出。
- [ ] 不出現 XP、懲罰、倒數、落後或虛構精通率。

### 16.5 驗證矩陣

- Node 單元測試：queue、比例、碰撞去重、回鍋、掃描集合、事件衍生統計。
- Python／資料測試：若 migration 或 Sheet 同步腳本有變更，驗證資料契約與總數。
- Transport 測試：實際 mock／integration 驗證 pull、push、logout race、account switch、offline merge。
- Browser QA：手機窄版、桌面版、重整、PWA 背景化、音檔切卡、中途離開。
- Production 驗證：部署後比對核心資產 hash，並以全新頁面完成至少一個四軌回合 read-back。

## 17. 不變原則

1. 完整掃描的前進速度不能被到期 backlog 永久餓死。
2. 第一次作答保存真實能力，回鍋答對保存教學成果；兩者不互相覆蓋。
3. 辨認與主動輸出是兩種能力，資料與進度分開。
4. queue 可以丟掉重建，學習事實不能丟。
5. 所有個人化規則都要能用一句話解釋。
6. 先用現有課程與教師音檔，把基礎流程做穩，再考慮語音 AI。
7. 學習進度用具體事實呈現，不用壓力和假分數推動。

## 18. 已確認決策

1. 產品優先順序為 B ＞ A ＞ C。
2. 採四軌動態混合型，不採固定比例到底，也不採黑箱全自適應。
3. 每次建立 10–15 分鐘小回合；約 1 小時仍是可分段的柔性衝刺目標。
4. 常態比例為 Sweep 40%／Due 30%／Weak 20%／Output 10%。
5. 錯題最多回鍋 2 次，第一次結果不被補救結果覆寫。
6. 完整掃描以 stable card ID 的 unaided first response 集合判定，不用扁平游標。
7. Output 使用中文提示、口頭作答、自我評估，不錄音、不做語音辨識。
8. 進度頁不顯示未定義的總精通率。
9. 新功能之前先修同步資料遺失、帳號競態、resweep 跳卡與音檔狀態。
10. 本規格確認後另寫實作計畫，不直接跳進開發。
